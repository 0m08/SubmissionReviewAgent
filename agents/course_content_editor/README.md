# Course Content Editor

A chat-driven Claude Managed Agent that edits a course's **slide chunks** and
**research notes** in a Google Sheet, from plain-language feedback. Built as
the backend for a future review UI (out of scope here): the frontend will
show before/after diffs for the user to accept or reject; this repo is the
console-testable backend that produces those diffs' inputs.

```
> The research notes for Shutoff and Control Valves ramble past the LO.

I'll trim the section on automatic valves — it's not in scope for this LO.
[tool: Bash]
Done — Research Notes for that block shortened, identity fields untouched.
```

## Relationship to the other two agent folders

| Folder | Status | Role here |
|---|---|---|
| `agents/slide_chunks_skills/` | **Trusted, live-deployed.** The checklist agent. | Source of the deploy.py/chat.py pattern and the original `working-with-google-sheets` skill this one forks from. |
| `agents/slide_chunk_editor/` | **Not trusted — code unreviewed.** | Only its `analysis/` output (`editing-priors.md`) is reused here, copied verbatim as `skills/editing-course-content/references/editing-priors.md`. None of its code was reused. |
| `agents/course_content_editor/` | **This folder.** | A clean fork of the *trusted* pattern, extended to cover research notes, with its own skills/, environment, and `deploy_state.json`. Shares nothing live with the other two — editing this folder cannot affect the deployed checklist agent. |

One thing this build fixed along the way: `slide_chunk_editor`'s prior work
had edited files inside `agents/slide_chunks_skills/skills/working-with-google-sheets/`
— the *live* checklist agent's skill directory — before this session started.
That was reverted to its pre-existing state; nothing here touches it.

## What's new here vs. the trusted checklist skill

The checklist agent never writes research notes back to the sheet — it only
*reads* them for review context. This agent needs to, so:

1. **`context/*.md` uses a new block format.** The old format joined each
   subtopic/LO's notes with a bare `\n\n---\n\n`, which is ambiguous — verified
   against a real course sheet that `research_notes` content contains its own
   `---` section divider. The new format gives every LO row an explicit
   `###LO ID:` marker, the same style `###Block ID:` already uses safely.
2. **`commit_context.py` is new.** It re-reads the live `Final Outline` tab
   fresh and overwrites only the matched rows' `research_notes` cell —
   verified against a real sheet that `Final Outline` carries ~20 columns
   beyond Topic/Subtopic/LO/Research Notes (references, source links,
   `context_0..3`, `rn_order`, `inline_image_placement_status`,
   `slide_chunks`, …), so reconstructing the tab from the `.md` files the way
   `commit_workspace.py` does for slide chunks would have destroyed them.
3. **Row identity for research notes is `(Topic, Subtopic, Learning
   Objectives)`**, not `(Topic, Subtopic)` — verified against a real sheet
   that the pair is *not* unique (one subtopic can carry several LOs) but the
   triple is. The editing skill treats those three fields as read-only for
   exactly this reason.
4. **`prepare_context_workspace.py` is new.** `prepare_workspace.py` (both the
   trusted original and this fork) always requires a valid slide-chunks tab —
   topic segmentation is derived from it — and errors out if that tab is
   missing or empty, even for a request that never touches a slide. This
   sibling script builds a research-notes-only workspace straight from the
   `Final Outline` tab, with no slide-chunks dependency at all. The system
   prompt routes between the two based on what the user actually asked for.
   Both write the identical `context/*.md` format, so `commit_context.py`
   works unchanged against either.

Both new pieces were run end-to-end against a real course sheet before
anything else was built on top of them (see "Verification" below).

## Layout

```
agents/course_content_editor/
├── managed_agent_config.yaml   # name, model, tools, system prompt — trusted config shape
├── deploy.py                   # one-time: upload skills, create env, create agent
├── chat.py                     # REPL against the deployed managed agent
├── deploy_state.json           # generated by deploy.py — agent/env/skill ids
└── skills/
    ├── working-with-google-sheets/   # forked from the trusted checklist skill
    │   ├── SKILL.md
    │   ├── references/parsing-rules.md
    │   └── scripts/
    │       ├── _common.py                    # unmodified copy + new shared context helpers
    │       ├── check_auth.py                 # unmodified copy
    │       ├── list_tabs.py                  # unmodified copy
    │       ├── prepare_workspace.py           # forked — new context block format
    │       ├── prepare_context_workspace.py   # NEW — research-notes-only, no slide-chunks tab needed
    │       ├── commit_workspace.py            # unmodified copy — slide chunks -> new tab
    │       └── commit_context.py              # NEW — research notes -> new tab
    └── editing-course-content/
        ├── SKILL.md
        └── references/editing-priors.md   # copied verbatim from slide_chunk_editor/analysis
```

No local-`.xlsx` path, no memory store, no criteria-editor — kept deliberately
minimal per the ask: a simple agent with sheet access and edit ability. Add
those later if the product needs them.

## Setup

Same deps the other two agents already use: `anthropic`, `pyyaml`,
`python-dotenv`, `gspread`, `pandas`. Nothing new to install if you've already
run either of the other two agents in this repo.

## Deploying

```bash
export ANTHROPIC_API_KEY=...
export GDRIVE_SA_B64=...          # base64-encoded service account JSON
./.venv/Scripts/python.exe agents/course_content_editor/deploy.py
```

Creates the two skills, the environment (egress locked to
`sheets.googleapis.com` / `oauth2.googleapis.com`), and the agent. IDs persist
to `deploy_state.json` — re-running updates in place rather than orphaning
resources. `--force-reupload-skills` pushes a new skill version even if the
content hash is unchanged; `--reupload-sa` rotates the service account.

Deploying without `GDRIVE_SA_B64` set is allowed — the agent gets created, but
`chat.py` will refuse to start a session without a service-account file id.

## Chatting

```bash
./.venv/Scripts/python.exe agents/course_content_editor/chat.py \
  --sheet-url "https://docs.google.com/spreadsheets/d/.../edit"
```

Or free-form, then paste the sheet URL as your first message. `/quit` or
Ctrl-D ends the session. Tab names vary per course sheet (e.g. one real
course sheet used `MAin Slide Chunks`, not `Slide Chunks`, as its tab name)
— tell the agent the tab name if you know it, or let it run `list_tabs.py`.

## Verification already done

Before any editing skill or agent config was written, both new/changed
scripts were run against a real course sheet with zero edits:

```bash
S=agents/course_content_editor/skills/working-with-google-sheets/scripts
WS=/tmp/cce_test_ws
python $S/prepare_workspace.py --sheet-url "<real sheet>" --workspace $WS \
  --source-tab "MAin Slide Chunks" --outline-tab "Final Outline" \
  --target-tab "scratch-test" --outline-target-tab "scratch-outline-test"
python $S/commit_workspace.py --workspace $WS --target-tab "scratch-test"
python $S/commit_context.py --workspace $WS --outline-target-tab "scratch-outline-test"
```

Result: `commit_context.py` matched 18/18 rows with 0 unmatched and 0
ambiguous, confirming the `(Topic, Subtopic, Learning Objectives)` identity
key holds on real data. `commit_workspace.py` (unmodified from the trusted
skill) reproduced its documented malformed-block behavior on 2 of 54 rows —
pre-existing behavior, not something this fork introduced. Scratch tabs were
deleted afterward.

`prepare_context_workspace.py` was verified the same way after it was added:
against the same real sheet, `--outline-tab "Final Outline"` alone (no
`--source-tab`, no slide-chunks tab touched at all), producing a workspace
with only `context/`. `commit_context.py` matched 18/18 rows with 0
unmatched/ambiguous against it too — same commit script, same result, on a
workspace that never depended on the slide-chunks tab existing. Scratch tab
deleted afterward.

**Not yet tested:** an actual agent turn making an edit and writing it back.
That's the next thing to run once `deploy.py` has been executed — try a small
research-notes request first (lower blast radius than a slide merge), confirm
`commit_context.py`'s warnings surface correctly if you deliberately ask the
agent to change a Learning Objective's wording (it should refuse or the write
should be reported as unmatched).

## What this does NOT do (yet)

- No diff-approve loop — that's the frontend's job, deferred per your
  request. This backend can be exercised via the console/chat REPL in the
  meantime.
- No memory store / durable preferences — add if the product needs it later,
  following the checklist agent's pattern (`ensure_memory_store` in its
  `deploy.py`).
- No local `.xlsx` workflow — Google Sheets only, per the ask.
